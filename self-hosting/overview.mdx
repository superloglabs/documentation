Superlog's application is open source under the Apache License 2.0. The repository is [superloglabs/responder-oss](https://github.com/superloglabs/responder-oss), where the project is named Responder. It contains the web app, API, worker, shared domain code, and database migrations. The hosted service at [superlog.sh](https://superlog.sh) runs the same code.

## Architecture

Superlog runs as two long-running Node.js services that share one Postgres database.

```text
Browser / providers
        │ HTTPS
        ▼
  control plane (web app + API)
        │
        ├── authentication and workspace configuration
        ├── encrypted integration credentials
        └── durable jobs ─────────────┐
                                      ▼
                                   worker
                             ┌────────┼────────┐
                             ▼        ▼        ▼
                          sandbox   model   providers
```

- **Control plane.** Serves the React app and the API. Handles sign-in, workspaces, integration setup, webhooks, and job scheduling.
- **Worker.** Claims jobs from Postgres, starts sandboxes, runs agents, and stores transcripts and results. It needs no inbound traffic.
- **Sandboxes.** Runs execute in [Daytona](https://daytona.io) sandboxes. Workspace secrets are stored in Daytona's write-only vault.

## Turn on automations

New workspaces get the automations product only when the deployment enables it. Set this on the control plane:

```bash
RESPONDER_NEW_ORGANIZATION_CAPABILITIES=automations,simplified_navigation
```

This applies to workspaces created after you set it. With it, new workspaces open on **Automations** and the sidebar matches these docs: **Automations**, **Integrations**, **Tag mode**, and **Settings**.

Automations that use included usage, rather than a workspace's own API key or ChatGPT subscription, run through Vercel AI Gateway. Set `AI_GATEWAY_API_KEY` to enable them.
