This guide sets up two alerts for one service, `checkout`, and posts both to a Slack channel:

- An error alert that fires when the service records too many error spans in 5 minutes.
- A latency alert that fires when the service's p95 span duration is above 800 ms.

Alerts compare one value with a threshold. They count errors; they don't compute an error ratio. Pick a count threshold from the service's normal traffic.

## Before you start

- Your service sends traces to Superlog. See [Instrument your app](/guides/instrument-your-app).
- Slack is connected. See [Slack](/integrations/slack). For a private channel, invite the Superlog app first.

## Alert on an error spike

<Steps>
  <Step title="Start a new alert">
    Open **Alerts** and click **New alert**. Name it `Checkout errors`.
  </Step>
  <Step title="Choose the data">
    Set **Data source** to **Spans** and leave **Only spans with an error status** on. Set **Service** to `checkout`.
  </Step>
  <Step title="Look at normal volume">
    Set **Preview time range** to the last 24 hours and click **Run search**. Note how many error spans a normal 5 minutes has.
  </Step>
  <Step title="Set the threshold">
    Set **Trigger when value is** to **Above** and enter a **Threshold** above that normal level. Set **Over the last** to **5 minutes** and **Check** to **Every minute**. The **Threshold preview** shows where past data would have crossed it.
  </Step>
  <Step title="Post to Slack">
    Under **Where to notify**, choose your **Slack channel**. Click **Create alert**.
  </Step>
</Steps>

To alert on error logs instead, set **Data source** to **Logs** and **Severity** to **Error**.

## Alert on p95 latency

<Steps>
  <Step title="Start a new alert">
    Click **New alert** and name it `Checkout p95 latency`.
  </Step>
  <Step title="Choose the data">
    Set **Data source** to **Spans** and **Service** to `checkout`.
  </Step>
  <Step title="Measure the 95th percentile">
    Open **Advanced settings**. Set **Measure** to **95th percentile** and **Field** to **Duration**. Changing the measure turns off **Only spans with an error status**, so the alert reads every span.
  </Step>
  <Step title="Set the threshold">
    Set **Trigger when value is** to **Above**, **Threshold (ms)** to `800`, and **Over the last** to **5 minutes**.
  </Step>
  <Step title="Post to Slack">
    Choose the same **Slack channel** and click **Create alert**.
  </Step>
</Steps>

To cover several services with one alert, leave **Service** empty, set **Group by** to **Service**, and turn on **Alert for each group**. Each service then fires and recovers on its own.

## What you get in Slack

When an alert fires, Superlog posts one message with the value, the threshold, a chart, and a **View alert** link. When the value is back within the threshold, it replies in the same thread. See [Alerts](/telemetry/alerts#when-an-alert-fires).

To have an agent investigate each firing, add an automation with a Slack trigger on the same channel. See [Triggers](/automations/triggers#slack).

## Ask an agent to set it up

An agent connected to the [Superlog MCP server](/api-reference/mcp) can create the same alerts. For example:

```text
Alert #checkout-alerts when checkout's p95 span duration is above 800 ms
over 5 minutes. Preview the rule first and tell me the current value.
```

The agent should:

1. Call `list_services` to confirm the service name and `list_slack_channels` to get the channel ID and integration ID.
2. Call `preview_alert` with the draft rule. It returns the current value and whether it is past the threshold, without saving anything.
3. Call `create_alert` with the same rule, a name, and the Slack channel.

The p95 rule looks like this:

```json
{
  "name": "Checkout p95 latency",
  "source": "traces",
  "aggregation": "p95",
  "field": "duration",
  "filter": { "service": "checkout" },
  "comparator": "gt",
  "threshold": 800,
  "windowMinutes": 5,
  "evaluationIntervalSeconds": 60,
  "slack": { "channelId": "C0123456789", "integrationAccountId": "<integration ID>" }
}
```

For the error alert, use `"aggregation": "count"`, drop `field`, and add `"statusCode": "STATUS_CODE_ERROR"` to `filter`.

To keep alerts in version control, export them with **Copy as Terraform** or `export_terraform`. See [Terraform](/developer/terraform).
