The Superlog browser SDK sends errors, sessions, traces, and Web Vitals as standard OpenTelemetry over OTLP/HTTP. It has three packages:

- `@superlog/browser`: error capture, breadcrumbs, user and attributes, sessions, `fetch` and `XMLHttpRequest` tracing, navigations, and Web Vitals.
- `@superlog/react`: an error boundary, React 19 root error handlers, and route patterns from React Router.
- `@superlog/sourcemaps`: a Vite plugin and a CLI that upload your source maps, so errors show and group by the original code.

The source is at [github.com/superloglabs/browser](https://github.com/superloglabs/browser).

## Install

```bash
npm install @superlog/browser @superlog/react
```

## Relay through your server

Superlog's ingest endpoint does not answer browser CORS requests, so a page cannot send to it directly. Add a route on your own server that forwards OTLP to Superlog with your ingest key. The key stays on the server.

This example is a Next.js route handler. Any server that can forward a request works the same way.

```ts app/api/otel/v1/[signal]/route.ts
// https://us.superlog.sh for a workspace in the US region.
const superlog = "https://superlog.sh";

export async function POST(request: Request, { params }: { params: Promise<{ signal: string }> }) {
  const { signal } = await params;
  if (signal !== "logs" && signal !== "traces") return new Response(null, { status: 404 });

  const headers = new Headers({
    "content-type": request.headers.get("content-type") ?? "application/x-protobuf",
    "x-api-key": process.env.SUPERLOG_INGEST_KEY!,
  });
  const encoding = request.headers.get("content-encoding");
  if (encoding) headers.set("content-encoding", encoding);

  const response = await fetch(`${superlog}/api/ingest/v1/${signal}`, {
    body: await request.arrayBuffer(),
    headers,
    method: "POST",
  });
  return new Response(response.body, {
    headers: { "content-type": response.headers.get("content-type") ?? "application/json" },
    status: response.status,
  });
}
```

The SDK sends only logs and traces. Anyone who can load your page can send through the relay, so add your own checks, such as a rate limit, if you need them.

## Start the SDK

Call `init` before the app renders. Point `endpoint` at your relay. The SDK adds `/v1/logs` and `/v1/traces` to it.

```ts
import { init, setUser } from "@superlog/browser";

init({
  service: "storefront",
  endpoint: `${window.location.origin}/api/otel`,
  release: import.meta.env.VITE_RELEASE,
  environment: import.meta.env.MODE,
  // Cross-origin APIs that should continue the trace. Same-origin requests always do.
  tracePropagationTargets: ["https://api.example.com"],
});

setUser({ id: user.id, email: user.email });
```

- `service` is sent as `service.name`, `release` as `service.version`, and `environment` as `deployment.environment.name`.
- `ignoreUrls` keeps requests, such as analytics, out of traces and breadcrumbs.
- `tracesSampleRate` keeps a share of traces, from 0 to 1. Errors are always sent.
- `beforeSend` can change or drop any error, and `beforeBreadcrumb` any breadcrumb.

## React

Add the error handlers to your root and instrument the router so errors carry the route pattern:

```tsx
import { ErrorBoundary, reactErrorHandler } from "@superlog/react";
import { instrumentRouter } from "@superlog/react/router";
import { createBrowserRouter, RouterProvider } from "react-router";

const router = createBrowserRouter(routes);
instrumentRouter(router);

createRoot(document.getElementById("root")!, {
  onCaughtError: reactErrorHandler(),
  onRecoverableError: reactErrorHandler(),
}).render(
  <ErrorBoundary fallback={({ reset }) => <button onClick={reset}>Try again</button>}>
    <RouterProvider router={router} />
  </ErrorBoundary>,
);
```

With declarative routes, use `SuperlogRoutes` in place of `<Routes>`:

```tsx
import { SuperlogRoutes } from "@superlog/react/router";

<SuperlogRoutes>
  <Route path="/orders/:orderId" element={<Order />} />
</SuperlogRoutes>
```

`@superlog/react` needs React 18 or later, and React Router 6.4 or later for the router integration.

## Capture errors yourself

```ts
import { addBreadcrumb, captureException, captureMessage, setAttributes } from "@superlog/browser";

try {
  await pay(cart);
} catch (error) {
  captureException(error, { attributes: { "payment.provider": "stripe" } });
}

addBreadcrumb({ category: "checkout", message: "payment started" });
setAttributes({ "app.plan": "pro" });
captureMessage("checkout took longer than 5s", "warning");
```

## Upload source maps

Source maps let Superlog map minified stack frames back to the original file, line, and function before it groups errors. Uploads use a workspace API key from [Settings → API keys](/settings/api-keys), not the ingest key.

With Vite, add the plugin:

```ts vite.config.ts
import { superlogSourceMaps } from "@superlog/sourcemaps/vite";

export default defineConfig({
  plugins: [superlogSourceMaps({ release: process.env.RELEASE })],
});
```

The plugin builds hidden source maps, writes a debug ID into each file and its map, uploads the maps with `SUPERLOG_API_KEY`, and deletes them from the output. A failed upload is printed and the build still succeeds. Set `failOnError: true` to fail the build instead.

For other bundlers, run the CLI on the build output:

```bash
SUPERLOG_API_KEY=... npx superlog-sourcemaps upload dist --release "$RELEASE" --delete
```

Uploads go to `https://superlog.sh`. For a workspace in the US region, pass `url: "https://us.superlog.sh"` to the plugin, or `--url https://us.superlog.sh` to the CLI.

## What gets captured

Each error is an OpenTelemetry log record at ERROR severity, so it appears in [Errors](/telemetry/errors) and [Logs](/telemetry/logs). It carries:

| Attribute | Value |
|---|---|
| `exception.type`, `exception.message`, `exception.stacktrace` | The error. Causes follow the stack as `Caused by:` |
| `exception.mechanism` | `onerror`, `onunhandledrejection`, `react`, or `manual` |
| `exception.handled` | Whether the app caught it |
| `app.breadcrumbs` | The last clicks, navigations, console messages, and requests |
| `app.debug_ids` | The debug ID of each file in the stack, for source maps |
| `url.full` | The page |
| `url.template` | The route pattern, with the React Router integration |
| `react.component_stack` | The component stack, from React |
| `session.id` | The session, on every log and span |
| `user.id`, `user.email`, `user.name` | From `setUser`, on every log and span |

The SDK also sends:

- Spans for `fetch` and `XMLHttpRequest` calls, which appear in [Traces](/telemetry/traces).
- Logs for page loads and navigations, page load timing, and Web Vitals (LCP, INP, CLS, FCP, and TTFB).

These errors are dropped before sending:

- `Script error.` without details, and the ResizeObserver loop notice.
- Errors whose frames all come from browser extensions or from `denyUrls`.
- Errors that match `ignoreErrors`.
- The same error repeated within a second.
- Errors past 30 per minute. Change this with `maxErrorsPerMinute`.
