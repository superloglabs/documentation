An automation hands a task to a coding agent. Each time one of its triggers fires, Superlog starts a fresh sandbox, checks out your repositories, and runs the agent on the task.

## What starts a run

| Source | Events |
|---|---|
| Slack | A new message in a channel, an app mention, or both |
| Sentry | A new issue or a regression |
| Superlog errors | A new error or a regression, in workspaces with [telemetry](/telemetry/errors) |
| Axiom, SigNoz, Honeycomb | A monitor or alert fires |
| Better Stack | An incident starts |
| DevRev | A new ticket |
| GitHub | A pull request is opened or merged |
| Discord | The automation command in a channel |
| Schedule | Every hour, day, or week, or a custom cron |
| Webhook | An HTTP request from any system |

You can also start a run by hand with **Run now**, or try one out with **Test**. An automation can have up to 10 triggers. See [Triggers](/automations/triggers).

## What the agent can do

- **Read and change your code.** Up to 10 GitHub repositories are checked out in the sandbox. The agent can run commands, tests, and builds there.
- **Use your tools.** [Connectors](/automations/connectors) give the agent Slack, Sentry, Datadog, Linear, custom MCP servers, and workspace secrets.
- **Follow your playbooks.** [Skills](/automations/skills) add reusable instructions and scripts to a run.
- **Open pull requests.** Pull requests from runs are listed under [PRs](/automations/pull-requests). Review comments on them continue the run that opened them.
- **Report back.** The agent replies in the Slack or Discord thread that started the run. It can also post to Slack channels and create Linear issues. Other runs can send results to Slack [notification](/automations/runs#notifications) channels.
- **Take follow-ups.** Reply in the run, or in its Slack thread, and the agent continues in the same sandbox with the same context. See [Runs](/automations/runs).

## What teams automate

| Area | Examples |
|---|---|
| Support | Answer support and community questions from the code and docs. Match reports to known errors. |
| Bug triage | Investigate alerts from Sentry, Datadog, Grafana, Axiom, SigNoz, Honeycomb, and Better Stack. Fix bugs reported in Slack. Fix regressions. |
| Scheduled reviews | Reliability checks, and reviews of observability, performance, architecture, and test coverage. |

Each of these is a template. See [Templates](/automations/templates).

## Models

Every automation picks its model and agent harness: Codex, Claude Agent SDK, or OpenCode. Runs can use your own API keys, your ChatGPT subscription, or the usage included in your plan. See [Models and harnesses](/automations/models).

## Limits

| Setting | Limit |
|---|---|
| Instructions | 50,000 characters |
| Triggers | 1 to 10 |
| Repositories | 1 to 10 |
| Slack or Discord channels per trigger | 50 |
| Sentry projects per trigger | 100 |
| Notification channels | 10 |
| Run time | 30 minutes |
