Integrations connect Superlog to the tools you already use. Connections belong to the workspace. Some tools take one connection per project, account, or access level, such as Langfuse, Supabase, Google Cloud, and AWS. Credentials are encrypted before storage and scoped to your workspace.

## Connect an integration

- **During setup.** The telemetry sources, GitHub, Slack, and Linear connect from [setup](/findings/quickstart), and later from **Setup → Sources**.
- **From Integrations.** Open **Integrations**, find the tool under **Marketplace**, and click **Add**. Connected tools move to **Connected integrations**, where **Manage** opens their settings.

Depending on the tool, you approve access on the provider's site, paste an API key, or create a stack in your cloud account.

## What each integration is used for

**Findings source**: Superlog finds problems in this tool's data. **Investigation context**: Superlog reads it while it investigates. **Automations**: it can start [automations](/automations/overview) as a trigger, or give them tools as a [connector](/automations/connectors).

### Code and collaboration

| Integration | Used for |
|---|---|
| [GitHub](/integrations/github) | Code Superlog reads to find the cause. Issues and pull requests that show a problem is known. Automations open pull requests. |
| [Slack](/integrations/slack) | The findings channel. Channels Superlog searches for known issues. Automation triggers and tag mode. |
| [Linear](/integrations/linear) | Issues that show a problem is already tracked. Automations create issues. |
| [Discord](/integrations/discord) | The `/automate` command starts automations. |
| [DevRev](/integrations/devrev) | New tickets start automations. |
| [Custom MCP](/integrations/custom-mcp) | Tools from your own MCP server for automations and tag mode. |

"Sweeps" means Superlog checks the tool on a schedule only when none of your telemetry reaches Superlog. See [How findings work](/findings/how-it-works#where-problems-come-from).

"Slack alerts" means the tool posts alerts to a Slack channel, and a Slack **New message in channel** trigger on that channel starts the automation.

## How access is limited

- Investigations only read. Superlog offers them only the read-only tools of each connection, including connections that allow writes for automations.
- Provider credentials stay outside the sandbox that reads your code. Superlog calls the provider for the agent.
- In automations, Datadog and custom MCP servers can pass through tools that write. Scope the credentials you give them.
- Supabase allows writes only with **Full database SQL access**, and never in investigations.

See [Security](/security) for more detail.
