Responder integrations fall into two categories: **triggers** — the events that start an investigation — and **context sources** — the tools Responder queries while an investigation is running. Most integrations act as context sources, feeding Responder the logs, metrics, code, and issue history it needs to reach a conclusion. A smaller set also serve as triggers, firing an agent the moment something goes wrong. Some integrations, like Slack and GitHub, play both roles.

All credentials you connect are encrypted at rest in your workspace. Responder never shares credentials across workspaces, and each integration account is scoped to the workspace that created it.

## How integrations are categorized

| Integration | Role |

| Slack | Trigger · Reporting · Context |
| Sentry | Trigger · Context |
| Datadog | Trigger (via Slack) · Context |

| GitHub | Context · Remediation (PR creation) |
| PostHog | Context (via Slack alerts) |
| Grafana Cloud | Context |
| Grafana Self-hosted | Context |
| Axiom | Context |
| Upstash | Context |
| Langfuse | Context |
| Supabase | Context |
| Vercel | Context |
