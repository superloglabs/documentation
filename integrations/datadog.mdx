Superlog reads your Datadog monitors, logs, traces, and metrics. Datadog alerts can start automations through a Slack channel.

## Connect Datadog

<Steps>
  <Step title="Open the Datadog page">
    Open **Setup → Sources**, click **Add source**, and choose **Datadog**. Or, in **Integrations**, click **Add** on Datadog. Choose your **Datadog site**.
  </Step>
  <Step title="Create keys in Datadog">
    In Datadog, open **API Keys** and create or copy a key. Then open **Application Keys** and create a scoped key owned by you or a service account. Datadog shows the application key only once.
  </Step>
  <Step title="Connect">
    Paste the **API key** and **Application key**, and click **Connect Datadog**. Both keys are stored encrypted.
  </Step>
</Steps>

## How findings use Datadog

- **Sweeps.** If none of your telemetry reaches Superlog, Superlog checks Datadog every 15 minutes for new problems. It looks at monitors first, then error-tracking issues, log patterns, traces, and metrics. A problem that a firing monitor already covers is not raised. See [How findings work](/findings/how-it-works#where-problems-come-from).
- **Investigations.** Superlog queries Datadog for evidence and impact while it investigates any problem. Investigations use only Datadog's read-only tools.

## Let agents read Datadog

Add Datadog as a connector. The agent uses Datadog's MCP server for your site. In automations, Superlog passes its tools through without filtering, so the application key's scope is the limit on what the agent can do.

The **Reliability check**, **Review observability**, **Review performance**, and **Fix regressions** templates use Datadog. See [Templates](/automations/templates).

## Start automations from Datadog alerts

Send Datadog monitor notifications to a Slack channel. Then add a Slack **New message in channel** trigger on that channel. Recovery notifications are ignored. No Datadog webhook is needed.

## Tag mode

Tag mode can read Datadog when you turn it on for tag mode.
