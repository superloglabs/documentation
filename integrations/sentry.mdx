Sentry starts automations when errors appear and gives agents the issue details they need to find the cause.

## Connect Sentry

In **Integrations**, click **Add** on Sentry and approve the Superlog app for your Sentry organization. Superlog syncs the projects your account can see.

The Sentry card shows whether the connection works and how many projects it found. If a check fails, select the card to reconnect.

## Start automations from Sentry

Add a Sentry trigger and pick up to 100 projects:

- **New issue** when Sentry creates an issue.
- **Issue regression** when a resolved issue comes back.
- **New issue or regression** for both.

The run is titled with the Sentry short ID and issue title. See [Triggers](/automations/triggers#sentry).

The **Triage new Sentry issues** and **Fix regressions** templates are a good starting point. See [Templates](/automations/templates#bug-triage).

## Let agents read Sentry

Add Sentry as a connector so the agent can look up issues, events, traces, and projects through Sentry's MCP server. This is useful for automations triggered from Slack or a schedule, such as matching a support report to a known error.

Tag mode can read Sentry when you turn it on for tag mode.

## Self-hosted setup

Self-hosted deployments need their own public Sentry integration.

| Setting | Value |
|---|---|
| Redirect URL | `<public-url>/api/integrations/sentry/callback` |
| Webhook URL | `<public-url>/api/webhooks/sentry` |
| Resource subscriptions | `issue.created`, `issue.unresolved` |
| Permissions | Organization: Read, Project: Read, Event: Read |
| Verify install | Enabled |

Set `SENTRY_APP_SLUG`, `SENTRY_CLIENT_ID`, and `SENTRY_CLIENT_SECRET`. Superlog checks every webhook signature against the client secret. See [Environment variables](/self-hosting/environment).
